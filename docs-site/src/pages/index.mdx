## How it compares

<div className="form-please-comparison">

| | Form, Please | React Hook Form | TanStack Form | Formik |
| --- | --- | --- | --- | --- |
| Schema library | Any Standard Schema | Any, via resolvers | Any Standard Schema | Yup, or a validate function |
| Field paths checked against the schema | Yes | Yes | Yes | No, string names |
| Fields generated from a definition | Yes | No | No | No |
| Grid layout declared in the definition | Yes, `columns` and `span` | No | No | No |
| Conditional fields and arrays declared, not hand-wired | Yes | No | No | No |
| Dependent values commit with their sources | Yes, `beforeUpdate` | No, `useEffect` and `setValue` | Field listeners, after the change | No, `useEffect` and `setFieldValue` |
| Submit receives the transformed output type | Yes | With a resolver | No, input values only | No |
| Design system | Wrapped once per kit | Wired per field | Wired per field | Wired per field |
| Escape hatch | Full React Hook Form API | Is the API | Full TanStack API | Full Formik API |
| Draft persistence and undo history | Optional entries | No | No | No |
| Devtools | Optional entry | Official package | Official package | No |

</div>

Checked against each library's documentation in September 2026. Open an issue
if a row is stale.

## What stays explicit

Each part of a form has one owner: the schema, React Hook Form, the definition,
the kit, or your application. Read [Ownership](/how-it-works#ownership).

Use RHF `register`, `Controller`, and hooks such as `useWatch` when a generated
definition is not enough. Read [You keep the React Hook Form
API](/how-it-works#you-keep-the-react-hook-form-api).
